Electron applications and VS Code open real windows, so the tests need a display. On Windows and macOS they run on the desktop. On Linux, you choose:

- **Hidden** on a virtual X server, Xvfb: for CI, and for local runs that should leave your desktop alone.
- **Visible** in a separate Xephyr window, which shows the run apart from your other windows.
- **On your normal desktop.**

## Display profiles

RobotCode's `robot.toml` can run the tests through a `wrapper` command, and each profile can have its own. The example project defines three display profiles, which this repository uses as well, and a profile `small-screen` that changes their screen size:

<Code code={robotToml} lang="toml" title="robot.toml" />

Choose one with `-p`, and combine it with other profiles:

```sh
robotcode -p xvfb robot                          # hidden on a Full HD Xvfb screen
robotcode -p xephyr robot                        # in a separate Full HD Xephyr window
robotcode -p local robot                         # on the normal desktop
robotcode -p xvfb -p small-screen robot          # hidden, on a 1280×800 screen
robotcode -p xvfb -p locator-override robot      # hidden, with another profile
```

- **Linux only:** `xvfb` and `xephyr` are switched on only on Linux, through `enabled.if`. Without a display profile, the tests run on the desktop.
- **Wayland:** on a Wayland desktop, Electron applications and VS Code follow `WAYLAND_DISPLAY` and `XDG_SESSION_TYPE`, and would open their windows on the desktop even under Xvfb. Both wrappers therefore remove `WAYLAND_DISPLAY` and set the session type to X11. `env` in `robot.toml` cannot remove a variable, which is why `env -u` sits in the wrapper.
- **Screen size:** `SCREEN_SIZE` sets the screen of both profiles, default `1920x1080`. Set it in a profile with `extend-env`, as `small-screen` does, or in the shell, for example `SCREEN_SIZE=1280x800 robotcode -p xvfb robot`. `extend-env` keeps the variables that other selected profiles set, where `env` would replace them.
- **Window manager:** both profiles start the window manager Openbox on their display, if it is installed, so that `Maximize Window` and `Minimize Window` work there. Without it, the tests still run with windows at their default size, and `Set Window Size` still sizes them, but maximising and minimising fail after the timeout.
- **Packages:** `xvfb` needs Xvfb, from the package `xvfb` on Debian and Ubuntu or `xorg-server-xvfb` on Arch Linux. `xephyr` needs Xephyr, from `xserver-xephyr` or `xorg-server-xephyr`. Openbox comes from the package `openbox`.

## Without RobotCode

With plain `robot`, put `xvfb-run` in front. On a Wayland desktop, also remove `WAYLAND_DISPLAY` and set the session type to X11:

```sh
xvfb-run -a -s "-screen 0 1920x1080x24" robot tests
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 xvfb-run -a -s "-screen 0 1920x1080x24" robot tests
```

`-a` picks a free display number, so several runs can use Xvfb at the same time.

## Screen size

Without `-s`, `xvfb-run` starts a screen of only 640×480, which is too small for useful screenshots. The display profiles use Full HD.

A window keeps the size that the application gives it, until a test calls `Set Window Size`. Maximised with `Maximize Window` and a window manager, it fills the screen; [Videos and traces of VS Code](../../vscode/videos-and-traces/#a-full-frame-of-vs-code) shows this for VS Code.

## VS Code and Electron on CI

The libraries download nothing, so a step of the CI job prepares VS Code or Electron before the tests, in the paths that `robot.toml` names. For VS Code, `@vscode/test-electron` downloads a fixed version; for an Electron app, the npm package `electron` brings the binary on the first `require('electron')`. The getting-started pages for [VS Code](../../vscode/getting-started/#vs-code) and [Electron apps](../../electron/getting-started/#an-app-from-source) show both. To keep the downloads between CI runs, cache their folders: `.vscode-test`, the default of `@vscode/test-electron`, and Electron's cache folder, `~/.cache/electron` on Linux or the folder that `electron_config_cache` names.
